# Концепция МАС "Нефтекод 2026" — производство дизтоплива (АВТ → гидроочистка 24-2000)

## 1. Цепочка процесса и границы данных

Пакет данных покрывает АВТ (`avt_tags.csv`, 71 тег КИП) и установку 24-2000 / гидроочистка
(`242000_tags.csv`, 26 тегов), плюс ЛИМС (лабораторные анализы по точкам отбора),
поточный анализатор ПАК (сера, расчётная D15) и справочник ВАК — 19 готовых линейных
регрессионных формул, связывающих теги КИП (и в двух случаях — последнее известное
значение ЛИМС) с показателями качества по разным фракциям/точкам отбора.

Блендинг (смешение компонентов товарного ДТ) в выданных данных тегами не представлен —
модуль блендинга реализуется как расширяемая заглушка с синтетическими долями компонентов,
структурно гарантирующая сумму = 100%, а не как модель, обученная на реальных тегах. Это
явное допущение, вынесенное в конфиг и в объяснение оператору.

## 2. Архитектура агентов

```
Data Agent → Quality Agent ─┐
           → Reliability Agent ─┤→ Optimization Agent → Orchestrator → [HITL] → Impact Agent → мониторинг отклика
```

- **Data Agent** — time-based as-of синхронизация ЛИМС/ПАК/телеметрии (без сопоставления по
  номеру строки), контроль полноты/актуальности (возраст каждого источника), детектор
  аномалий (rolling z-score по КИП-тегам), единицы измерения — из справочника тегов.
- **Quality Agent** — прогноз показателей качества через ВАК-формулы (детерминированные,
  без ML/LLM), доверие к прогнозу = f(возраст ЛИМС-инпутов формулы, невязка ВАК против
  последнего факта ЛИМС), риск выхода за спецификацию (сера ≤ 10 мг/кг и др.).
- **Reliability Agent** — прокси-индекс тяжести режима: скользящий z-score/перцентиль
  отклонения ключевых тегов от исторической рабочей области + скорость изменения
  (rate-of-change) как признак резких переключений режима. Допущения по каждой прокси-
  метрике зафиксированы явно (см. `config/params.py`).
- **Optimization Agent** — генерирует кандидатные сценарии как малые возмущения (шаги
  сетки) вокруг текущей точки по ограниченному списку управляемых параметров (см. п.3),
  отбрасывает варианты, нарушающие жёсткие ограничения, сравнивает оставшиеся по
  Парето-фронту (качество / риск оборудования / выпуск / энерго-прокси).
- **Orchestrator** — не LLM-«мозг» для расчётов: детерминированный шаг-логгер в стиле
  ReAct (Thought/Action/Observation по каждому вызову агента), который вызывает агентов по
  порядку из ТЗ (п.1 логики цикла), разрешает конфликт целей через Парето-выбор
  Optimization Agent, формирует ответ оператору строго в 7-блочном формате из ТЗ (Время и
  состояние / Проблема-риск / Действие / Эффект / Проверка ограничений / Уверенность /
  Объяснение). Явная генерация текста объяснения — шаблонная (подстановка реальных чисел),
  LLM опционально подключаема только для стилизации готового текста, не для чисел.
- **Impact Agent** — после подтверждения оператором (HITL: confirm / reject / запросить
  альтернативу) формирует «воздействие» (запись изменения уставок) и переводит систему в
  режим мониторинга отклика — сравнение прогноза с фактическим откликом на следующих тиках.

## 3. Управляемые параметры (кандидаты, обоснование — тег есть в КИП и физически
задаёт режимную уставку, а не только измеряет)

АВТ: `F3` (орошение К1), `F5` (пар К1), `F19` (острое орошение К2), `F26/F27/F28/F29`
(пар в К6/К7/К9/К2), `F30/F32/F34` (расходы отбора фракций 290-350/240-290/150-250 —
определяют кривую разгонки и, соответственно, ВАК T50/T90/D15), `T55` (температура
выхода печи П3 — севериметр АВТ), `F45` (холодный гудрон в К10).

24-2000: `Q21`/`F9` (соотношение газ/сырьё — прямо упомянуто в ТЗ), `P8` (температура
ГСС на входе реактора Р-202 — жёсткость гидроочистки), `F15` (квенч в реактор Р-202),
`W4` (расход бензина в К-206, стабилизация).

## 4. Жёсткие ограничения

1. Сера в товарном ДТ ≤ 10 мг/кг (сверка ВАК-прогноза и последнего ПАК/ЛИМС по правилу
   приоритета источников).
2. Доли компонентов блендинга = 100% (структурно, по построению модуля).
3. Управляемый параметр не выходит за консервативный модельный диапазон
   (диапазон — явно помечен как допущение эксперимента, не как паспортный предел).
4. При устаревших/неполных данных выше порога свежести — отказ от рекомендации с
   объяснением причины.
5. Рекомендация не переводит индекс тяжести режима в «недопустимый» класс.

## 5. Харнесс (симуляционная среда)

Реплей исторических тиков (10 мин) с 4 переключаемыми сценариями:
`stable` (нормальный период, ожидаем «без изменений»), `quality_risk` (окно с реальным
приближением серы/цетана к спецификации), `degraded_data` (синтетическая порча:
задержка ЛИМС/ПАК, пропуски и выбросы в КИП), `full_cycle` (полный цикл: обнаружение →
рекомендация → HITL → воздействие → отклик).

## 6. Дашборд

Streamlit: таймлайн ключевых тегов и прогноза качества, индикаторы свежести ЛИМС/ПАК,
панели по каждому агенту, карточка рекомендации в 7-блочном формате ТЗ, таблица/Парето-
график сравнения сценариев, кнопки HITL (подтвердить/отклонить/альтернатива), журнал
ReAct-трассировки оркестратора, переключатель из 4 сценариев демо.
