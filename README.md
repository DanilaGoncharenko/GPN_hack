# Нефтекод 2026 — МАС управления производством дизельного топлива

Прототип мультиагентной системы для цепочки **АВТ → гидроочистка 24-2000 → контроль качества / блендинг**.
Система получает состояние процесса, проверяет свежесть и полноту источников, оценивает качество и тяжесть режима, строит **контрфактический прогноз серы после изменения уставки**, отбрасывает небезопасные сценарии через отдельный **Safety Gate**, сравнивает допустимые варианты и формирует объяснимую рекомендацию оператору с Human-in-the-loop.



### Sulfur Forecast Agent

Строит хронологический surrogate для `Q21` — поточного анализатора серы гидроочищенного дизельного топлива. Модель прогнозирует **изменение серы относительно текущего Q21**, а затем восстанавливает будущий уровень.

Модель:

- обучается только на данных **до заданного cutoff**;
- использует лаги технологических параметров;
- выбирает горизонт из 30 / 60 / 120 минут по временной validation;
- поддерживает контрфактический режим: можно изменить текущий `T6`, `F22`, `F14`, `F9` и другие подтверждённые управляющие параметры и получить прогноз последствий;
- возвращает `p50` и консервативную верхнюю границу `upper = p50 + q90(abs(error))`.

Верхняя граница используется не как статистический доверительный интервал, а как **экспериментальный safety margin**, калиброванный на временной validation.

### Constraint Agent

Это отдельный hard gate перед Pareto-оптимизацией.

Проверяет:

- `upper sulfur <= 10 мг/кг`;
- отсутствие критического режима по proxy-индексу надёжности;
- все уставки внутри явно заданных модельных диапазонов;
- пригодность входных данных.

Экономический или производственный proxy не может отменить отказ Safety Gate.

### Blending Agent

Роль присутствует явно, однако **не выдумывает управление блендингом**.
В выданном пакете отсутствуют подтверждённые компонентные потоки/доли коммерческого блендинга, поэтому агент возвращает статус `unavailable` с объяснением причины.

## Архитектура цикла

```text
┌──────────────┐
│  Data Agent  │  телеметрия / ЛИМС / ПАК / freshness
└──────┬───────┘
       ↓
┌──────────────┐
│ Quality Agent│  ВАК + текущая сера
└──────┬───────┘
       ↓
┌────────────────────┐
│ Sulfur Forecast     │  что будет через H минут
│ Agent               │  при текущем и новом режиме
└──────┬─────────────┘
       ↓
┌──────────────────┐
│ Reliability Agent│  тяжесть режима / proxy риска
└──────┬───────────┘
       ↓
┌──────────────────┐
│ Constraint Agent │  HARD SAFETY GATE
└──────┬───────────┘
       ↓
┌───────────────────┐
│ Optimization Agent│  Pareto среди допустимых сценариев
└──────┬────────────┘
       ↓
┌──────────────────┐
│ Orchestrator      │  рекомендация + объяснение
└──────┬────────────┘
       ↓
   Operator HITL
       ↓
┌──────────────────┐
│ Impact Agent      │  мониторинг отклика
└──────────────────┘

Blending Agent работает как отдельная роль доступности данных и не выдаёт
фиктивные доли компонентов, если подтверждённых входов в пакете нет.
```

### Источники серы

Для текущей оценки качества действует приоритет:

```text
ЛИМС → ПАК
```

В телеметрии 24-2000 используется `Q21` — поточный анализатор серы в гидроочищенном ДТ.
Он используется Sulfur Forecast Agent как плотный временной target для surrogate; при пропусках целевая история может дополняться предыдущим ПАК-измерением по времени.

## Управляемые параметры

В `src/oilhack/config.py` подтверждённые управляющие рычаги ограничены несколькими тегами АВТ и 24-2000.

Примеры:

```text
АВТ:
F3, F5, F19, F26, F27, F28, F29, F30, F32, F34, T55, F45

24-2000:
W4, T6, F9, F14, F22
```

Исторические 5–95 перцентили используются как **модельные экспериментальные диапазоны**, а не как паспортные промышленные ограничения.

## Контрфактический прогноз серы

Sulfur Forecast Agent тренируется без временной утечки.

На каждом сценарии cutoff ставится на `10 минут` до начала демонстрационного окна:

```text
training data <= scenario.start - 10 min
validation       — только более ранние точки внутри training window
```

Используемые горизонты:

```text
30 min
60 min
120 min
```

Выбирается горизонт с минимальной MAE на временной validation.

Для каждого кандидата оптимизатора изменение кодируется как:

```python
{"242000__T6": 370.0}
```

или:

```python
{"avt__F30": 120.0}
```

Это позволяет не путать одинаковые имена тегов из разных установок.

## Safety Gate

Порядок проверки принципиален:

```text
VAK / Reliability / Sulfur Forecast
            ↓
       Constraint Agent
            ↓
       только feasible
            ↓
        Pareto score
```

Минимальная hard-проверка по сере:

```text
predicted_sulfur_upper <= 10 мг/кг
```

Если контрфактический прогноз отсутствует, сценарий блокируется.

Таким образом, система может корректно отказаться от рекомендации вместо того, чтобы компенсировать риск повышением выпуска или условной экономией.

         → validation
         → test

## Важные допущения

- `307` в телеметрии трактуется как sentinel историзатора и маскируется в `NaN`.
- Для текущей серы приоритет имеют ЛИМС и ПАК.
- `Q21` используется как плотный временной сигнал в Sulfur Forecast Agent.
- Контрфактический прогноз — статистический surrogate, а не физическая causal model.
- Верхняя граница прогноза = `p50 + q90(actual - predicted)` на временной validation;
это односторонний экспериментальный safety margin для ограничения сверху.
Для counterfactual demo дополнительно действует явный экспериментальный clip
`|ΔS| <= 1.5 мг/кг`, чтобы surrogate не экстраполировал неустойчивый скачок за пределы обучающей области.
- Диапазоны управляемых параметров из `config.py` — консервативные модельные диапазоны.
- Reliability Agent использует proxy по отклонению от исторического режима и скорости изменения.
- Throughput/Energy пока представлены прозрачными proxy, а не реальными экономическими затратами.
- Блендинг не оптимизируется без подтверждённых компонентных потоков и долей.
- Оператор остаётся последним звеном принятия решения; система сама не меняет технологический режим.

## Что говорить на защите

Главное отличие текущей версии от исходного прототипа:

> Система не просто перебирает новые значения параметров и оценивает их по ВАК. Для каждого кандидата она сначала моделирует последствия изменения режима по сере, затем пропускает сценарий через независимый жёсткий Safety Gate и только после этого сравнивает допустимые варианты по Pareto-критериям.

Если безопасного сценария нет, система сообщает об этом оператору и не пытается компенсировать нарушение качества производительностью или стоимостью.

## Дашборд

Дашборд отражает фактические выходы МАС и не содержит отдельной бизнес-логики.
Он использует те же `CycleResult` / `Tick`, что и CLI-harness.

В интерфейсе доступны четыре основных представления:

1. **Обзор** — текущая рекомендация, сера, верхняя граница прогноза, тяжесть режима,
   полнота данных, динамика серы и статус решения во времени.
2. **Технологические данные** — управляемые параметры АВТ и 24-2000, а также все
   значения выбранного 10-минутного тика.
3. **Рекомендация** — объяснение в формате ТЗ и Human-in-the-loop: подтвердить,
   отклонить или запросить другой вариант.
4. **Аналитика агентов** — Quality / Sulfur Forecast / Reliability / Constraint /
   Optimization / Blending, таблица кандидатов, Pareto-график и полный trace.

Запуск:

```bash
PYTHONPATH=src streamlit run src/oilhack/dashboard/app.py
```

Для быстрой демонстрации без тяжёлого расчёта можно выбрать режим **«Демо»**.
Для защиты хакатона рекомендуется режим **«Реальные данные»**, где видны настоящие
исторические телеметрические ряды и результаты агентов.
